> take the run down.

<objective>
The second half of the phase goal: *one broken source cannot take the run down.* Plus the three
tests the Definition of Green names by requirement id, and the human-observed run that automated
checks cannot substitute for.

Three things land here, and each is a claim the earlier plans deliberately did not make:

1. **Failure isolation.** Exactly one `try`/`except` boundary per (creator, source) pair, no
   cross-pair state, no short-circuit. A dead YouTube key produces three logged failures and a
   `failure_count` of three, and the Twitch work still completes.
2. **The `runs` row a dying run still leaves.** Once the database is open, a `try`/`finally` always
   appends the row with the counts reached so far, and the original exception re-raises. This is
   what lets Phase 6 tell three states apart: the timer never fired, the job died part way, and the
   job completed with failures.
3. **The reader's door.** `connect(create=False)` raises a named error rather than creating an empty
   database at a mistyped path — the same silent-wrong-path failure Phase 2 D-08 exists to prevent,
   and the reason the collector stays the only writer in fact rather than by convention.

Purpose: ROADMAP's Definition of Green says a phase does not close on "it ran without crashing", and
from Phase 3 onward it additionally requires a human-observed end-to-end run against real data.
Both gates live here, and the second one cannot be automated by construction.

Output: `db.py`'s read path, `collector.py`'s failure boundary and `runs` guarantee, `tests/test_db.py`,
the rest of `tests/test_collector.py`, and five closed entries in `03-UAT.md`.

per (creator, source) pair. On an exception: emit one `logger.error` with lazy `%` arguments naming

Exactly one boundary at the pair level, and no second nested boundary split by creator and by
source — D-15 is explicit that one boundary gets full isolation and nesting two is the same
protection with more code. No cross-pair state and no short-circuit: a source that has failed three
times in a row still gets tried on the fourth creator. Short-circuiting was declined because it puts
a failure taxonomy and per-source state into the orchestrator, which ARCHITECTURE.md's Anti-Pattern 1

and the `finally` below is what guarantees the `runs` row in that case.

is appended with the counts reached so far whatever happens, and the original exception re-raises

stopped.
