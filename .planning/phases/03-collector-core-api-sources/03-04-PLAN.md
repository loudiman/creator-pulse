## Phase Goal

> Real numbers from YouTube and Twitch land in SQLite with history, and one broken source cannot
> take the run down.

*(ROADMAP `**Mode:** mvp` is set; the Phase 3 `**Goal:**` line is not in user-story form and is
reproduced verbatim rather than invented — see the planner's return note.)*

<objective>
Make the config file safe to edit. Today `load_creators()` is parse-only: a mistyped platform key
becomes a live dictionary key, a duplicated `id` becomes two creators that quietly overwrite each
other's row every day, and a missing field becomes a `KeyError` traceback three frames deep. All
three are edits an operator will actually make.

`validate()` walks the whole file, gathers every problem, names the creator and the field on each
one, and stops the run before the database is opened and before any network call.

The duplicate-`id` rule is the one that matters most and the one nothing else can catch.
`creator_id` is part of `UNIQUE (creator_id, source, metric_date)`, so two entries sharing an id
upsert over each other — one creator's numbers silently replace the other's, every single day, with
no error anywhere and no way to rebuild the history, because the APIs report current values only.

Purpose: CFG-03 asks for a message naming the offending creator and field rather than a bare
traceback. That is a user-facing contract, and it is the difference between the operator fixing the
file in thirty seconds and reading a stack trace.

Output: `validate()` and `ValidationError` in `config.py`, the gate in `cli.py`, and the D-12 rule
set covered case by case in `tests/test_config.py`.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `creators.yaml` -> application | An operator-authored file deserialised into live Python objects. This is the only untrusted-shaped input in the process. |
| creator id / name -> log format arguments | Values from that file reach `logger.error` calls that the journal retains. |
| creator id -> SQL primary-key component | The id becomes part of `UNIQUE (creator_id, source, metric_date)`; a collision is a silent daily data loss. |
