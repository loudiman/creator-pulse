Create `src/creatorpulse/sources/_retry.py` from RESEARCH.md's verified block. It lives in the source
layer and nowhere else — ARCHITECTURE.md Anti-Pattern 1 and D-13 both forbid the orchestrator knowing
about HTTP status codes or `requests` exception types, and the easiest way to violate that is to
"just add one small retry" in `collector.py` later. This module must import nothing from
`creatorpulse.sources`' own `__init__`, so the submodule import from a sibling source module resolves
cleanly while the package is still initialising.

`retry(fn, *, creator_id, source, max_attempts=3)` returns a wrapped callable with the same signature
(`ParamSpec` and a `Callable[P, requests.Response]` return type — mypy `strict = true` will not accept
a bare `Callable`). The retryable set is exactly D-13's narrow list and no wider: the exception tuple
is `(requests.Timeout, requests.ConnectionError)`, and the retryable statuses are `429` and anything
`>= 500`. Everything else returns on attempt 1. Retrying every `requests.RequestException` was
rejected because a configuration error would then look like a network problem in the journal for
seven seconds before failing anyway.

Backoff is fixed: `time.sleep(2.0 * attempt)`, giving 2s then 4s, with no jitter and no reading of
`Retry-After` or `Ratelimit-Reset` (D-14). This job makes roughly thirteen API calls a day from one
box that nothing else shares, so header-aware waiting would be code that never runs; the documented
trigger to revisit is header handling becoming necessary, at which point a retry library is the
upgrade path. Do not add one now.

On the last attempt, a retryable *status* is returned rather than raised, so the caller's
`raise_for_status()` produces the real error; a retryable *exception* re-raises. Sleep only between
attempts, never after the last one — three attempts means two sleeps, seven seconds worst case, and a
test asserts the sleep count.

The log line is one `logger.info` per retry with lazy `%` arguments, naming the identifier, the
source, and the attempt number, and **nothing else**. It must never carry the request headers, the
params dict, the client secret, the API key, or a bearer value (T-03-04). Note deliberately, so
nobody "fixes" it: the parameter is called `creator_id` but a source module only ever holds the
`creators.yaml` *identifier*, not the creator's slug id — the identifier is how the config names that

| environment -> outbound request | `TWITCH_CLIENT_ID` and `TWITCH_CLIENT_SECRET` cross into a POST body; the minted bearer crosses into every subsequent request header. |

  real failure in the journal is what settles it.
