## Phase Goal

> Real numbers from YouTube and Twitch land in SQLite with history, and one broken source cannot
> take the run down.

*(ROADMAP `**Mode:** mvp` is set, but the Phase 3 `**Goal:**` line is not in "As a / I want to / so
that" form. It is reproduced verbatim above rather than invented into a user story — see the
planner's return note.)*

<objective>
Answer, with one real call, the question that can invalidate the Twitch half of this phase before a
line of `sources/twitch.py` is written — and capture every fixture the rest of the phase's tests
read while making it.

Two questions, one call (RESEARCH.md Open Question 1, STATE.md blocker):

1. Does `GET /helix/videos` return a usable `view_count` under an **app** access token? RESEARCH.md
   assumption A2 is community-sourced, because `dev.twitch.tv` was unreachable during research. The
   sibling endpoint `/helix/channels/followers` is known to reject app tokens outright, and this
   phase's entire Twitch metric rests on the assumption that the wall does not generalise.
2. Does `period=month` actually filter? RESEARCH.md Pitfall T1 cites three independent forum threads
   (2018, 2021, March 2025) reporting the parameter is ignored.

Recording `videos_ok.json` *is* that call, so the fixture costs nothing extra.

Purpose: if `view_count` is unreachable, the Twitch metric needs rethinking on day one, not day
five. This plan is deliberately the phase's first wave and deliberately not the tracer — it produces
a journal entry and eight fixture files, not a code path.

Output: a `--header` flag on the sanctioned recorder, eight recorded fixtures, a dated `journal.md`
finding, and the `03-UAT.md` scaffold.

**Branch, planned rather than assumed:** if the live call returns 401/403, or returns 200 with
`view_count` absent or zero on every archive, STOP. Do not start `03-03`. Record the refutation in
`journal.md` with the literal response, and return to the author — SRC-02's metric definition (D-05)
rests on this endpoint and a replacement is a decision, not an implementation detail.
</objective>
