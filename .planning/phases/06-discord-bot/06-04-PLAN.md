<objective>
Write down what this phase integrated and what it deliberately did not, and set up the human-observed
proof the ROADMAP requires before Phase 6 can close.

**User story (MVP):** **As** the person who has to defend this project out loud tomorrow, **I want**
the Discord API surface I chose to touch recorded with reasons, and the five success criteria set up
as a checklist with real evidence slots **so that** "why didn't you use embeds" and "did the digest
actually fire" both have answers I can point at instead of remember.

Two documents, no source files. It runs in the same wave as 06-05 and shares no file with it, so
either can be executed first and cutting 06-05 leaves this plan untouched.

Purpose: the api-coverage gate blocks the phase seal without `COVERAGE.md`, and Phase 5's criterion 5
is still PENDING because its write-up was deferred to the last hour. This plan exists partly so that
does not happen twice.

Output: `COVERAGE.md` and `06-UAT.md` in the phase directory.

**Decisions this plan implements, and where.** D-20 — the recorded coverage boundary: `COVERAGE.md`
and `06-UAT.md` together state in writing which half of this phase automated tests do not reach, and
name the human gate that proves it instead (both tasks). D-21 — the unit file was agent-written under
a dated, scoped exception and is already committed; the control that replaces hand-writing is ROADMAP
criterion 5, which closes only when the author installs the unit themselves and writes the intents
explanation into `06-UAT.md` unaided (Task 2). D-14 — the criterion-4 entry is written to survive
06-05 being cut, naming the cut-order decision rather than being dropped (Task 2).

**Decisions this plan deliberately implements by *not* doing something.** No task performs any
Developer Portal step and no task runs `systemctl` — `.claude/CLAUDE.md` Hard Rule 3 binds this phase
in full, and the 2026-08-06 amendment to Hard Rule 1 narrowed only the *writing* of unit files into
`deploy/`, never their installation.
