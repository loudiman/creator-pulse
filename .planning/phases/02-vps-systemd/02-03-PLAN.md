## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-2-07 | Repudiation | unattended timer fires | medium | mitigate | `systemctl list-timers`' `LAST` column plus `journalctl -u creatorpulse.service` are systemd's own persisted trigger record (`/var/lib/systemd/timers/`), which is also what `Persistent=` reads. No application-side heartbeat file is built — duplicating that state in the app is redundant and can drift from the real trigger history. |
| T-2-08 | Tampering | UAT evidence | medium | mitigate | Task 2 checks the pastes against documented systemd behaviour rather than accepting them: an exact `NEXT`, a single catch-up run, an 08:00 Asia/Manila elapse equal to 00:00 UTC. A mismatch goes to `## Gaps`, never to a pass. D-15 requires greppable pasted text specifically so it can be re-checked later. |
| T-2-04 | Elevation of Privilege | the timer-activated service process | medium | mitigate | The service runs as the non-root `creatorpulse` user (D-02, human-built unit) whether started by hand or by the timer; timer activation adds no privilege. |
| T-2-03 | Information Disclosure | journald | medium | mitigate | Only the two resolved paths and the four Phase 1 run lines reach the journal; no secret-bearing variable is read or logged by Phase 2 code. |
| T-2-SC | Tampering | npm/pip/cargo installs | low | mitigate | No package-manager install task exists in this plan; enforced by the `git diff --quiet HEAD -- pyproject.toml src/ tests/ .env.example` acceptance criterion in Task 2. |
