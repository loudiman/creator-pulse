<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| systemd (PID 1, root) → service process (`User=creatorpulse`) | Secrets cross here. PID 1 parses `EnvironmentFile=` as root and injects the values *before* dropping privilege, so the service user never needs read access to its own secrets (D-04). |
| git working tree → public GitHub | The repository is public (D-03). A committed secret is a published secret. |
| `/etc/creatorpulse/creatorpulse.env` → the filesystem | A root-owned mode-600 file outside the git working tree, where `git clean -xfd` cannot delete it and `git add -f` cannot commit it. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-2-01 | Information Disclosure | git history, all branches | high | mitigate | Task 2 asserts `git ls-files` and `git log --all --diff-filter=A --name-only` contain no env, service-account, credentials, or token file, and runs `git log --all -S` per variable name. Failure is not suppressed by an `|| echo` fallback. Recovery from a positive hit is rotation, and the plan says so rather than offering a revert. |
| T-2-02 | Information Disclosure | `/etc/creatorpulse/creatorpulse.env` | high | mitigate | `root:root` mode `600`, outside the git working tree (D-04), parsed by PID 1 before the drop to `User=creatorpulse`. Verified by pasted `stat -c '%a %U:%G'` output in `02-UAT.md` entry 3 and gated by a literal `600 root:root` acceptance criterion. |
| T-2-03 | Information Disclosure | journald | medium | mitigate | `systemctl cat` is inspected for the absence of secret values (D-07 keeps only paths in the unit); Phase 2 application code reads exactly two named environment keys and never enumerates the environment. |
| T-2-04 | Elevation of Privilege | the service process | medium | mitigate | `User=creatorpulse`, a dedicated non-root account (D-02, human-built unit).
