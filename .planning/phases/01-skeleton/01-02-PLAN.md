- **OPS-04 (`pytest` passes against saved fixtures, no live network calls) — probe status
  `unresolved`, category `concurrency`.** Planner assumption for Phase 1: the suite has no shared
  mutable state, no temp files, and no ordering dependency, so an interrupted or parallel run
  guarantees exactly what a serial run does. The single test is a pure read of a committed file. The
  assumption stops holding the moment Phase 3 adds SQLite-backed tests that share a database path —
  at that point the guarantee has to be restated (per-test temp database, or a serial marker), and it
  is Phase 3's job to do so. No `pytest-xdist` is installed and none may be added, so parallel
  execution is not currently reachable.
</flagged_assumptions>

    Create `scripts/record_fixture.py` — the sanctioned way fixture files get created per D-16. It makes
    a live call and writes into `tests/fixtures/`; it is run by hand and never by pytest, which is what
    keeps OPS-04's ban on live network calls inside the suite intact. `[tool.pytest.ini_options]`
    `testpaths` is already scoped to `tests/`, so this file is outside collection by construction.

    **Scope boundary, stated so it is not exceeded.** This is a generic fetch-and-save utility with zero
    knowledge of any platform. It must not contain a YouTube, Twitch or TikTok endpoint, must not parse
    a response body, must not import playwright, and must not resemble a source adapter. Those are
    Phase 3 and Phase 4 artifacts. What lands here is: take a URL, save the bytes, name the file
    correctly.

    Give it an `argparse` interface with four options: `--source` (the fixture subdirectory, e.g. the
    source module name), `--case` (the scenario name), `--url` (the public page or endpoint to record),
    and `--ext` defaulting to `json`. Expose `main(argv: list[str] | None = None) -> int` and guard the
    call under a `__main__` check.

    **Validate both name segments before opening any connection.** Reject `--source` and `--case`
    unless each matches `^[a-z0-9_]+$` — that pattern admits no path separator, no dot, and no
    parent-directory reference, which is what stops a crafted argument from writing outside the fixture
    root. Print the offending value and return 2 on rejection. Do this first, before the fetch, so a bad
    argument costs nothing and touches no network. As a second belt, resolve the composed target path
    and assert it is relative to the resolved `tests/fixtures` directory before writing.

    Fetch with `requests`, which is already a pinned runtime dependency, using an explicit timeout —
    never an unbounded one. Raise on a non-2xx status rather than silently saving an error page as a
    fixture: a fixture that is really a 403 body is worse than no fixture, because it makes a Phase 3
    parser test pass against the wrong shape. Create the target directory with parents as needed, write
    the response text as UTF-8, and print the path written.

    Keep it lint-clean and format-clean — `ruff check .` and `ruff format --check .` both cover
    `scripts/`. It is outside the `mypy src/` target, but annotate it anyway; it costs three lines and
    keeps the file readable.
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator-supplied `--source` / `--case` → filesystem write path | Untrusted-shaped strings are joined into a path the script writes to |
| remote URL → local fixture file | Bytes from a public internet endpoint are persisted into the repository |
| test suite → network | The suite must be provably unable to reach the network (OPS-04) |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-04 | Tampering | `scripts/record_fixture.py` path composition from `--source` and `--case` | medium | mitigate | Both segments must match `^[a-z0-9_]+$` before any connection is opened — the pattern admits no separator, dot, or parent reference. A resolved-path containment assert backs it up. Two acceptance criteria exercise the rejection path with a live exit-code check. |
| T-01-05 | Information disclosure | A recorded fixture body committed into a public repository | medium | mitigate | The recorder targets public unauthenticated pages only, per the project's ethics rule. `tests/fixtures/README.md` records that fixtures are reviewed before commit. No authenticated request path exists in Phase 1, so no token can appear in a recorded body. |
| T-01-06 | Spoofing | A non-2xx or interstitial response saved as if it were a real fixture | medium | mitigate | Raise on non-2xx rather than writing the body. A 403 or challenge page saved as a fixture would make a later parser test pass against the wrong shape — a silently wrong green. |
| T-01-07 | Denial of service | An unbounded fetch hanging the operator's shell | low | mitigate | Explicit request timeout; the script is hand-run and single-shot, never scheduled. |
| T-01-08 | Repudiation | A live network call sneaking into the pytest suite | low | mitigate | `testpaths` is scoped to `tests/`, the recorder lives in `scripts/`, and an import grep over `tests/` runs as an acceptance criterion every execution. |
</threat_model>
