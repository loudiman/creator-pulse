## Verified Apps Script facts (RESEARCH.md, checked against primary Google docs — do not re-derive)

1. **A function literally named `onEdit(e)` is a *simple* trigger and cannot call `UrlFetchApp`.**
   `[VERIFIED]` against `developers.google.com/apps-script/guides/triggers`: simple triggers "can't
   access services that require authorization." SCRIPT-03 therefore requires an **installable**
   onEdit trigger bound to a differently-named function. This is the single load-bearing fact in
   the phase.
2. **`ScriptApp.newTrigger(name).forSpreadsheet(ss).onEdit().create()`** is the installable form.
   `ScriptApp.getProjectTriggers()` enumerates only *this script project's* triggers, so deleting
   all of them before creating is safe and is the duplicate-guard D-09 asks for.
3. **`e.oldValue` and `e.value` are documented as "only available if the edited range is a single
   cell."** A multi-cell paste or fill-down leaves both undefined. `e.user` is unreliably populated
   and D-14 declines to use it.
4. **`PropertiesService.getScriptProperties().getProperty(key)` returns `null` for an unset key**
   — `[ASSUMED — MEDIUM]`, which is why the guard is a falsy check rather than `=== null`. A falsy
   check catches `null`, `undefined`, and the empty string identically.
5. **Discord's Execute Webhook endpoint returns `204 No Content` on success** (empty body); `200`
   with a body only when `?wait=true` is appended, which this phase does not need. Content is
   capped at 2000 characters, far beyond a one-line message.
6. **The manifest is hidden by default in a container-bound project.** Project Settings (gear) →
   tick "Show `appsscript.json` manifest file in editor" before it can be pasted over.

Create the `apps-script/` directory with exactly two files. Write the whole design in one pass —
do not build a simplified handler and patch it afterwards, and do not add a `.gitignore` entry:
both files are meant to be committed in full, which is D-04's entire point.

**`apps-script/appsscript.json`.** Three keys, strict JSON, no comments. `timeZone` set to
`Asia/Manila` and `runtimeVersion` set to `V8` — both load-bearing per CONTEXT's discretion list.
`exceptionLogging` set to `STACKDRIVER`. Omit `oauthScopes` entirely: Apps Script's own scope
detection covers `SpreadsheetApp`, `ScriptApp`, `PropertiesService` and `UrlFetchApp` usage, and an
explicit array is only needed to *narrow* below what the code requests. Note for the walkthrough,
and for RESEARCH.md Pitfall 3: `timeZone` here and `.inTimezone(...)` on the trigger builder in
05-02 are **two settings, not one** — the manifest governs `Utilities.formatDate` defaults and is
the fallback the builder inherits when `.inTimezone()` is omitted; the builder call is what actually
pins the fire time. Both are set to the same value deliberately.

**`apps-script/Code.gs`.** Global functions only — Apps Script has no module system and no imports,
so there is nothing to translate from Python beyond the conventions. Open with a short file-header
comment naming the file as the Phase 5 Apps Script layer, stating that it is synced to the Sheet by
pasting this file whole (never by hand-editing in the browser), and naming the Sheet's frozen tab
and Status column so a reader hits the contract before the code.

Declare these as top-of-file `const`s, in this order, each with a one-line comment naming the
decision it comes from. Top-of-file constants over inlined literals is CONTEXT's stated preference
because the walkthrough reads better when the numbers are collected:

- `DASHBOARD_TAB` = the tab title `Dashboard` (Phase 4 D-03).
- `STATUS_COLUMN` = `7` (column G, frozen by Phase 4 D-03).
- `CREATOR_COLUMN` = `1` and `SOURCE_COLUMN` = `2` (columns A and B, the values D-14's message names).
- `FIRST_DATA_ROW` = `2` (row 1 is the header; an edit to `G1` is not a Status edit).
- `WEBHOOK_PROPERTY` = the string `DISCORD_WEBHOOK_URL` (D-13).

05-02 appends four more constants beside these; leave room but do not pre-declare them.

`onOpen(e)` — a **simple** trigger, and correctly so: building a menu needs no authorization, and a
simple trigger is what makes the menu appear for anyone who opens the Sheet without anybody having
installed anything. Build the top-level menu named `CreatorPulse` via
`SpreadsheetApp.getUi().createMenu(...)`, add exactly one item labelled `Install triggers` bound to
the function name `installTriggers`, and call `.addToUi()`. Call `createMenu` exactly once — a
second call produces a second top-level entry. **Read no Sheet data in this function**: it must
build the menu unconditionally so that an empty, header-only, or entirely absent `Dashboard` tab
cannot suppress the menu. 05-02 inserts the other two items ahead of *Install triggers* in D-09's
stated order; a menu item may name a function that does not exist yet without breaking `onOpen`,
but there is no reason to add the labels before the functions, so do not.

`installTriggers()` — the deliberate ten lines D-09 pays for. Get `SpreadsheetApp.getActive()`.
Then, **before creating anything**, iterate `ScriptApp.getProjectTriggers()` and call
`ScriptApp.deleteTrigger(t)` on every one, counting them. That enumeration returns only this script
project's triggers, so deleting all of them cannot touch anything else. Then create exactly one
trigger in this plan: `ScriptApp.newTrigger('onStatusEdit').forSpreadsheet(ss).onEdit().create()`.
Finish with `SpreadsheetApp.getActive().toast(...)` reporting both numbers — how many were removed
and how many created. The counts are not decoration: they are what makes the duplicate-guard
*observable*, because clicking the item a second time must report "removed 1, created 1" rather
than "removed 0, created 1". Without the delete pass, two clicks means two triggers and one Status
edit posts twice. 05-02 adds the time-driven trigger to the same function.

`onStatusEdit(e)` — the installable trigger's target, and the reason for every naming choice in this
file. **Do not name this function after the simple-trigger event name** (the forbidden identifier is
the bare event name with `function` in front of it; an acceptance criterion counts its occurrences,
including in comments). Body, in order:

1. Take `e.range` into a local, and its sheet via `range.getSheet()`.
2. Guard and return early on three conditions, as one combined check or three: the sheet's
   `getName()` is not `DASHBOARD_TAB`; `range.getColumn()` is not `STATUS_COLUMN`; `range.getRow()`
   is below `FIRST_DATA_ROW`. Together these are exactly "act only on `Dashboard!G2:G`". The guard
   is cheap insurance and it is also the direct answer to "why does editing column A not post to
   Discord" in the walkthrough. Note in a comment that a gspread/API write does not fire onEdit at
   all — only human edits through the Sheets UI do — so the daily sync can never trigger this path.
3. Read the row once: `const row = range.getRow()`, then `sheet.getRange(row, CREATOR_COLUMN).getValue()`
   and `sheet.getRange(row, SOURCE_COLUMN).getValue()`.
4. Old value: `e.oldValue` when it is not `undefined`, else the literal `(blank)`. D-15 is explicit
   that a missing old value is rendered, never assumed — it is undefined for any multi-cell edit.
5. New value: prefer `e.value` when defined; when it is undefined fall back to `range.getValue()`,
   then render an empty/null result as the literal `(cleared)` and anything else as itself.
   **This fallback is a planner call worth flagging rather than absorbing.** D-15 requires a cleared
   cell to post `(cleared)`, and `e.value` is undefined both when the cell was cleared *and* when
   the edit spanned multiple cells — reading the cell back distinguishes the two, so a multi-cell
   paste does not report a clear that did not happen. It is one extra read and it removes a false
   statement from a message whose entire job is accuracy. The residual limitation, documented rather
   than engineered around: a multi-cell edit reports only its top-left row.
6. Call `postToDiscord` with the message built as creator, a space-slash-space, source, a
   space-em-dash-space, `Status: `, the old value, a space-arrow-space, and the new value — D-14's
   exact shape, e.g. `xqc / youtube — Status: (blank) → Flagged`.

Do not read `e.user` or put any editor identity in the message: it returns blank in many
configurations even for installable triggers, and D-14 declines it deliberately. Do not add it back
on the assumption it will populate.

`getWebhookUrl()` — `PropertiesService.getScriptProperties().getProperty(WEBHOOK_PROPERTY)`. Guard
with a falsy check rather than `=== null` (the return for an unset key is `[ASSUMED — MEDIUM]`, and
a falsy check catches null, undefined and empty string identically). On failure `throw new Error(...)`
with a message that names the property key **and** the Project Settings → Script Properties path
that fixes it — the same shape `sheets.py`'s `SheetsKeyfileUnusable` uses in Python: name the
missing setting, name the fix, in one string. A silent no-op is the wrong failure here for the same
reason it was in Phase 4 D-07 and PITFALLS.md §18(d): it looks identical to "nobody edited
anything." The thrown error's message must contain the property *key*, never a URL.

`postToDiscord(message)` — the shared poster, called by this plan's handler and by 05-02's watchdog.
Get the URL from `getWebhookUrl()`. Call `UrlFetchApp.fetch(url, options)` with `method` `post`,
`contentType` `application/json`, `muteHttpExceptions` true, and `payload` built by
`JSON.stringify` over an object holding `content` set to the message and `allowed_mentions` set to
an object whose `parse` is an empty array. Two deliberate choices, both cheap:

- **`JSON.stringify`, never string concatenation into a JSON body.** Status text is free-form and
  unvalidated by design (D-12 keeps column G free text), so a quote or a backslash typed into a
  Status cell would break a hand-built body. `stringify` escapes it by construction.
- **`allowed_mentions` with an empty `parse` array** suppresses `@everyone` / `@here` / role pings.
  RESEARCH.md flags this as a cheap real mitigation rather than a locked decision; it is taken here
  because column G is reachable by anyone holding the Sheet's edit link (the Sheet is link-editable,
  STATE.md) and one line that removes channel-wide pinging from that path is worth more than it
  costs. See T-05-04 and T-05-05.
